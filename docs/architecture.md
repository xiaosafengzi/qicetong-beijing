# 架构与业务覆盖

## 目标

以北京政策事项建立“材料导入 → 事实确认 → 条件核查 → 证据报告”的预审流程。确定性规则完成条件计算，模型承担可选的材料理解和 Nexent 工具编排。

```mermaid
flowchart LR
  A[官方政策与年度通知] --> B[带出处的版本化规则]
  C[企业文档 表格 图片] --> D[解析及待审核候选]
  D --> E[人工确认的企业事实]
  B --> F[条件与受理窗口核查]
  E --> F
  F --> G[报告与证据依赖图]
  H[Nexent Agent 与 5 个 Skills] --> I[9 个 MCP 工具服务]
  I --> F
  I --> J[来源检索与版本影响分析]
  K[浏览器工作台] --> D
  K --> F
  J --> G
```

## 已实现机制

1. 政策规则具有独立 ID、原文 URL、条款定位、摘要、所需字段和会计期间。
2. 企业事实保存 value、unit、period、status 和 evidence 引用。缺失、未确认和冲突分别进入待补证或冲突处理。
3. 金额转为 Decimal 计算；元/万元/亿元显式换算；研发比例按三年金额合计计算，阈值由最近一年销售额决定。
4. SME 普通评分与直通车分支分别计算，两条路径均核查规模等基础条件。可选研发评分路径的数据缺失记为未知。
5. 企业材料导入产生待审核候选，新旧证据不一致时保留冲突。政策概念确认扩充概念库，规则发布由维护人员处理。
6. 报告保存实际使用的材料与政策证据，并对输入、规则和日期计算 SHA-256。之后改企业资料不改变历史报告。
7. 同一事项的政策版本按年度、日期、字段和期间比较，列出需复核规则，并对关联企业完整重算。
8. 上传政策在同一条款内提取术语、比较词、数值和单位，金额换算后生成变化候选。每个候选在内存副本中重算企业核查，列出受影响项；维护人员核验来源与上下文后配置生效规则。
9. 可选的本地 RapidOCR 对 PNG/JPG 逐行生成文字、图片框位置和候选字段。所有图片候选保持未核验状态，用户打开原图并逐项核对后才能确认；扫描 PDF 尚需先逐页转图。
10. 制造业来料抽检的合成规范与批次复用同一事实、规则和证据结构，三种状态均已测试。

## 方案选择

选择“结构化事实 + 规则检查 + 证据依赖图”，原因是当前案例少、关键阈值明确、可逐项验证。纯模型问答难以稳定保证金额、期间和条件边界；全量通用图数据库/图检索栈会增加部署成本，因此初版用 SQLite 保存实体和实际依赖图。

图中边表示材料出处和判断依赖。半自动建图采用种子术语候选、人工对齐、事实审核和数值规则候选。开放式本体发现、候选准确率与人工处理效率的对比评测是后续扩展项。

## 尚未自动化的业务条件

科技型中小企业的会计核算/税务口径、排除行业完整映射、最新信用记录及现场核验要求；高企的专家创新评分、知识产权核心关联、高新领域实质判断及特殊经营期处理。这些事项在页面、MCP 和报告中列为人工复核项。

## 后续实验

15 个模拟困难案例已完成确定性证据规则引擎与本地 Qwen3 8B 单模型基线对比，方法和结果见 `docs/evaluation.md`。后续使用业务人员独立标注的授权脱敏材料，覆盖满足、不满足、缺失、冲突和版本变更场景，测量证据定位准确率、人工修正次数、更新处理耗时、模型成本和时延。
