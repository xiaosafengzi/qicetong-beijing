# 上传政策变化预览

上传政策后，系统提取**待核验的门槛变化候选**，预览哪些企业及判断项受到影响。政策来源、效力和上下文由维护人员核验，生效规则通过人工配置更新。

## 数据流

1. 用户在“政策与材料”上传文字层 PDF、DOCX、表格或文本，系统保留文件 SHA-256、正文及页码/行号。
2. `qicetong/policy_change.py` 在同一条款内匹配领域术语、比较词、数字与单位。当前只覆盖三类数值上限（职工总数、年销售收入、资产总额）和两类明确比例（科技人员占比、高新产品收入占比）。“2 亿元”先转为 `20000 万元`；模糊表述和不兼容单位拒绝匹配。
3. 候选绑定现行政策 ID、规则 ID、原文片段、定位、原阈值和候选阈值。相同门槛也显示为“与现行配置一致”。
4. 对每个变化候选，内存中复制政策、替换一个阈值，对当前企业重算，并列出单项及总体状态变化；原政策与历史报告保持原样。
5. 维护人员核对发布机关、正式原文、适用地区、有效期、上下文和版本关系后，人工配置新的生效规则。

浏览器入口为政策文件详情中的“提取候选并预览影响”；REST 为 `GET /api/policy-change-preview?asset_id=...&policy_id=...&as_of=YYYY-MM-DD`；Nexent MCP 工具为 `preview_uploaded_policy_change`。

## 已验证的情况

- 国家科技型中小企业评价办法的公开条款“职工总数不超过500人、年销售收入不超过2亿元、资产总额不超过2亿元”可对齐 3 条现行规则，金额归一后识别为同一门槛。
- 高企公开条款中的“科技人员比例不低于10%”和“高新技术产品收入比例不低于60%”可对齐 2 条规则。
- 演示假设“职工总数不超过50人”及“科技人员比例不低于50%”可列出受影响的模拟企业，用于验证门槛调整后的影响预览。
- 模糊语句和错误单位不产生候选；API 测试确认预览后生效政策不变。浏览器端到端测试包含上传、预览和影响显示；Nexent 轨迹证明 Agent 实际调用了预览工具。

相关验证见 `tests/test_policy_change.py`、`tests/browser.cjs` 和 `runtime/nexent/smoke-agent-policy-change-results.json`，覆盖接口、浏览器和 Agent 工具调用链路。候选抽取的金标准准确率评测，以及开放式概念发现、复杂分档门槛、政策撤销、自动监测和增量图更新尚待补充。扫描 PDF 需先转图片，再核对 OCR 草稿。
